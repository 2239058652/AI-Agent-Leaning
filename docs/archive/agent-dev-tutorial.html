项目概览

你的项目是一个 AI 助手，核心业务是订单管理。用户通过自然语言与 AI 对话，AI 可以：

  • 只读查询：查订单列表、查今日统计
  • 聚合分析：统计今日订单数、成交额
  • 敏感写操作：取消订单（需要用户确认）
最小业务闭环：

用户提问 → 模型判断是否需要工具 → 调用工具 → 执行 → 返回结果 → 模型生成回复 → 前端展示
                                                          ↓
                                             如果是敏感操作 → 前端弹窗 → 用户确认 → 后端执行

阶段 0主线项目与业务边界

0.1 业务场景定义

三类操作的划分依据：

类型 工具 是否需要确认
只读查询 query_orders 直接执行
聚合分析 analyze_orders 直接执行
敏感写操作 cancel_order 必须走确认流程

为什么这样划分？

  • 只读操作不会修改数据，错了也没损失
  • 写操作会改变业务状态，必须有「刹车」机制
  • 这是 Agent 系统和普通 CRUD 的核心区别：模型不能直接执行破坏性操作

1.2 异常处理

BusinessException（业务异常）

@Getter
public class BusinessException extends RuntimeException {
    private final String code;  // 错误码，如 "VALIDATION_ERROR"

    public BusinessException(String code, String message) {
        super(message);
        this.code = code;
    }
}

作用：Service 层抛出明确的业务错误，而不是返回 null 或错误字符串。

优势：

  • 调用方不需要每个方法都写 if-else 判断返回值
  • GlobalExceptionHandler 统一处理
  • 错误码 + 错误消息，前端可以精确处理

GlobalExceptionHandler（全局异常处理器）

@Slf4j
@RestControllerAdvice
public class GlobalExceptionHandler {

    // 参数校验失败（@Valid 触发）
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ApiResponse<Void> handleValidation(MethodArgumentNotValidException ex) {
        String message = ex.getBindingResult().getFieldErrors().stream()
                .map(e -> e.getField() + ": " + e.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return ApiResponse.fail("VALIDATION_ERROR", message);
    }

    // 业务异常
    @ExceptionHandler(BusinessException.class)
    public ApiResponse<Void> handleBusiness(BusinessException ex) {
        return ApiResponse.fail(ex.getCode(), ex.getMessage());
    }

    // 兜底：未知异常
    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public ApiResponse<Void> handleUnknown(Exception ex) {
        log.error("未知异常", ex);
        return ApiResponse.fail("INTERNAL_ERROR", "服务内部错误，请稍后重试");
    }
}

关键注解：

  • @RestControllerAdvice = @ControllerAdvice + @ResponseBody，拦截所有 Controller 异常
  • @ExceptionHandler(XxxException.class) - 处理指定类型的异常
  • @ResponseStatus(HttpStatus.BAD_REQUEST) - 设置 HTTP 状态码
执行流程：

Controller 抛出异常 → GlobalExceptionHandler 捕获 → 返回统一格式 ApiResponse

流程：

2.1.2 流式（chatStream）

public void chatStream(ChatRequest request, SseEmitter emitter) {
    executor.execute(() -> {  // 异步执行，不阻塞主线程
        ChatClient chatClient = chatClientBuilder.build();
        var promptSpec = chatClient.prompt()
                .system(request.getSystemPrompt())
                .user(request.getMessage())
                .advisors(memoryAdvisor(request));

        Flux<String> flux = promptSpec.stream().content();  // 流式调用

        flux.subscribe(
            chunk -> emitter.send(SseEmitter.event().name("chunk").data(chunk)),  // 每收到一块就发给前端
            error -> emitter.completeWithError(error),                           // 错误时关闭
            () -> {                                                              // 完成时
                emitter.send(SseEmitter.event().name("done").data("[DONE]"));
                emitter.complete();
            }
        );
    });
}

关键点：

  • SseEmitter - 服务器推送事件（SSE）发射器
  • Flux<String> - Reactor 的响应式流，逐个发射数据块
  • subscribe(onNext, onError, onComplete) - 订阅流，注册三个回调

2.1.3 带工具流式（chatStreamWithTools）

public void chatStreamWithTools(ChatRequest request, SseEmitter emitter) {
    executor.execute(() -> {
        var toolCallbacks = toolCallbackProvider.getToolCallbacks();  // 获取工具列表

        ChatClient chatClient = chatClientBuilder.build();
        Flux<String> flux = chatClient.prompt()
                .system(request.getSystemPrompt())
                .user(request.getMessage())
                .toolCallbacks(toolCallbacks)  // 注册工具给 Spring AI
                .toolContext(Map.of("emitter", emitter))  // 传递带外数据（emitter）
                .advisors(memoryAdvisor(request))
                .stream()
                .content();

        flux.subscribe(/* 同上 */);
    });
}

关键点：

  • .toolCallbacks(toolCallbacks) - 注册工具，Spring AI 自动处理 Agent Loop
  • .toolContext(Map.of("emitter", emitter)) - 传递 emitter 给工具回调（用于发送确认事件）

@Data

3.2 ToolRegistry（工具注册表）

@Slf4j
@Component
@RequiredArgsConstructor
public class ToolRegistry {
    private final Map<String, ToolDefinition> tools = new LinkedHashMap<>();

    @PostConstruct
    public void init() {
        // 注册所有工具
        register(ToolDefinition.builder().name("get_current_date")...build());
        register(ToolDefinition.builder().name("query_orders")...build());
        register(ToolDefinition.builder().name("cancel_order").sensitive(true)...build());

        // 注册 MCP 工具
        registerMcpTools();
    }

    private void register(ToolDefinition definition) {
        tools.put(definition.getName(), definition);
    }

    public boolean isAllowed(String name) {
        return tools.containsKey(name);  // 白名单检查
    }

    public List<ToolDefinition> getAllTools() {
        return List.copyOf(tools.values());
    }
}

职责：

  • 集中管理所有合法工具
  • 提供白名单检查
  • 生成发给模型的 tools JSON

3.3 ToolService（工具执行服务）

@Slf4j
@Service
@RequiredArgsConstructor
public class ToolService {
    private final ToolRegistry toolRegistry;
    private final ToolValidator toolValidator;
    private final McpClientService mcpClientService;
    private final OrderService orderService;

    public ToolResult execute(String toolName, String argsJson) {
        // 1. 白名单检查
        if (!toolRegistry.isAllowed(toolName)) {
            return ToolResult.success("错误: 未知工具 " + toolName);
        }

        ToolDefinition toolDef = toolRegistry.getTool(toolName).orElseThrow();

        // 2. 敏感操作检查
        if (toolDef.isSensitive()) {
            return ToolResult.confirmRequired(toolName, argsJson);  // 返回"需要确认"
        }

        // 3. 参数校验
        ToolValidator.ValidationResult validation = toolValidator.validate(toolDef, argsJson);
        if (!validation.success()) {
            return ToolResult.success("错误: 参数校验失败 — " + String.join("; ", validation.errors()));
        }

        // 4. 执行工具
        String result;
        if (toolDef.getSource() == ToolDefinition.ToolSource.MCP) {
            result = executeMcpTool(toolName, argsJson);  // MCP 工具走远程
        } else {
            result = switch (toolName) {  // 本地工具走 switch
                case "query_orders" -> executeQueryOrders(argsJson);
                case "cancel_order" -> executeCancelOrder(argsJson);
                // ...
            };
        }

        return ToolResult.success(result);
    }
}
执行流程：

白名单检查 → 敏感操作检查 → 参数校验 → 路由到 MCP 或本地 → 执行 → 返回结果

3.4 ToolValidator（参数校验）

@Slf4j
@Component
@RequiredArgsConstructor
public class ToolValidator {

    public ValidationResult validate(ToolDefinition tool, String argsJson) {
        List<String> errors = new ArrayList<>();
        JsonNode schema = tool.getParameters();
        JsonNode args = new ObjectMapper().readTree(argsJson);

        // 校验必填参数
        JsonNode required = schema.path("required");
        if (required.isArray()) {
            for (JsonNode field : required) {
                String fieldName = field.asText();
                if (!args.has(fieldName) || args.path(fieldName).isNull()) {
                    errors.add("缺少必填参数: " + fieldName);
                }
            }
        }

        // 校验参数类型
        JsonNode properties = schema.path("properties");
        if (properties.isObject()) {
            var fieldIt = properties.fields();
            while (fieldIt.hasNext()) {
                var entry = fieldIt.next();
                String fieldName = entry.getKey();
                String expectedType = entry.getValue().path("type").asText("");
                String actualType = getJsonNodeType(args.path(fieldName));

                if (!expectedType.equals(actualType)) {
                    errors.add("参数 " + fieldName + " 类型错误");
                }
            }
        }

        return errors.isEmpty() ? ValidationResult.ok() : ValidationResult.fail(errors);
    }
}

3.5 ToolCallbackProvider（工具桥接）

@Slf4j
@Component
@RequiredArgsConstructor
public class ToolCallbackProvider {
    private final ToolRegistry toolRegistry;
    private final ToolService toolService;
    private final ObjectMapper objectMapper;

    public List<ToolCallback> getToolCallbacks() {
        return toolRegistry.getAllTools().stream()
                .map(this::createCallback)
                .toList();
    }

    private ToolCallback createCallback(ToolDefinition toolDef) {
        BiFunction<Map<String, Object>, ToolContext, String> toolFunction = (args, ctx) -> {
            String argsJson = objectMapper.writeValueAsString(args);
            ToolResult result = toolService.execute(toolDef.getName(), argsJson);

            if (result.isNeedsConfirmation()) {
                // 从 ToolContext 取出 emitter
                SseEmitter emitter = (SseEmitter) ctx.getContext().get("emitter");

                // 给前端发 confirmation_required 事件
                ObjectNode confirmEvent = objectMapper.createObjectNode();
                confirmEvent.put("toolName", result.getToolName());
                confirmEvent.put("argsJson", result.getArgsJson());
                emitter.send(SseEmitter.event().name("confirmation_required").data(confirmEvent));

                // 返回给模型的指令
                return "操作尚未执行。系统已在界面上弹出确认框，请告知用户在弹窗中点击确认或取消。";
            }

            return result.getResult();
        };

        return FunctionToolCallback.<Map<String, Object>, String>builder(toolDef.getName(), toolFunction)
                .description(toolDef.getDescription())
                .inputType(Map.class)
                .inputSchema(schema)
                .build();
    }
}

关键点：

  • 这是 Spring AI 和 ToolService 之间的桥梁
  • Spring AI 调工具时 → 走这个 callback → 委托给 ToolService
  • 敏感操作时 → 从 ToolContext 取 emitter → 发确认事件给前端

阶段 3.5工具安全边界

安全机制三层防护

第1层：白名单（ToolRegistry.isAllowed）
    ↓ 只允许注册过的工具执行
第2层：敏感操作检查（toolDef.isSensitive）
    ↓ 敏感操作返回"需要确认"，不直接执行
第3层：参数校验（ToolValidator.validate）
    ↓ 校验必填参数和类型
执行：ToolService.execute

敏感操作确认流程

模型调 cancel_order
↓
ToolService 检测到 sensitive=true
↓
返回 confirmRequired
↓
ToolCallbackProvider 从 ToolContext 取 emitter
↓
发 confirmation_required 事件给前端
↓
前端弹窗 → 用户确认
↓
调 /api/chat/execute-confirmed
↓
ToolService.executeConfirmed（跳过敏感检查）

4.1 SSE 解析（App.tsx）

const sendMessage = useCallback(async (text?: string) => {
    const response = await fetch(endpoint, {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ message: msg, conversationId: conversationIdRef.current }),
        signal: controller.signal,  // 用于中断
    })

    const reader = response.body?.getReader()
    const decoder = new TextDecoder()
    let eventName = ''  // 必须在循环外面！

    while (true) {
        const { done, value } = await reader.read()
        if (done) break

        buffer += decoder.decode(value, { stream: true })
        const lines = buffer.split('\n')

        for (const line of lines) {
            if (line.startsWith('event:')) {
                eventName = line.substring(6).trim()
            }
            if (line.startsWith('data:')) {
                const data = line.substring(5).trim()

                if (data === '[DONE]') continue

                if (eventName === 'chunk') {
                    assistantContent += data  // 累加文本
                } else if (eventName === 'tool_call') {
                    toolCallsRef.current.push(JSON.parse(data))  // 记录工具调用
                } else if (eventName === 'tool_result') {
                    toolResultsRef.current.push(JSON.parse(data))  // 记录工具结果
                } else if (eventName === 'confirmation_required') {
                    setConfirmState(JSON.parse(data))  // 弹窗
                }

                eventName = ''  // 重置
            }
        }

        // 更新 React state → 界面重新渲染
        setMessages(prev => {
            const updated = [...prev]
            updated[updated.length - 1] = {
                role: 'assistant',
                content: assistantContent,
                toolCalls: toolCallsRef.current,
                toolResults: toolResultsRef.current,
            }
            return updated
        })
    }
}, [input, loading, toolMode])

关键点：

  • eventName 必须在 while 循环外面声明，因为 event: 和 data: 可能被拆在两个 TCP 包里
  • 用 useRef 跟踪工具调用链路，避免 React 批处理导致丢失
  • 先插入一条空的 assistant 消息，后续所有更新都改最后一条

5.2 McpClientService（客户端）

@Slf4j
@Service
public class McpClientService {
    private final McpProperties mcpProperties;
    private McpSyncClient client;
    private boolean available = false;

    @PostConstruct
    public void init() {
        if (!mcpProperties.isEnabled()) return;

        // 1. 创建传输层
        var transport = HttpClientStreamableHttpTransport
                .builder(mcpProperties.getUrl())
                .build();

        // 2. 创建同步客户端
        client = McpClient.sync(transport)
                .requestTimeout(Duration.ofSeconds(30))
                .build();

        // 3. 协议握手
        client.initialize();

        available = true;
    }

    public List<Tool> listTools() {
        if (!available) return Collections.emptyList();
        return client.listTools().tools();  // 工具发现
    }

    public String callTool(String toolName, Map<String, Object> args) {
        if (!available) return "错误: MCP 客户端不可用";

        CallToolResult result = client.callTool(new CallToolRequest(toolName, args));

        // 提取文本内容
        StringBuilder sb = new StringBuilder();
        for (Content content : result.content()) {
            if (content instanceof TextContent text) {
                sb.append(text.text());
            }
        }
        return sb.toString();
    }

    @PreDestroy
    public void destroy() {
        if (client != null) client.close();
    }
}

关键点：

  • @PostConstruct - 启动时自动连接 MCP Server
  • @PreDestroy - 关闭时清理连接
  • McpClient.sync() - 同步客户端（还有异步版本 McpClient.async()）
  • HttpClientStreamableHttpTransport - HTTP 传输层（对应 MCP Server 的 Streamable HTTP）

5.3 MCP 工具注册（ToolRegistry.registerMcpTools）

private void registerMcpTools() {
    if (!mcpClientService.isAvailable()) return;

    List<McpSchema.Tool> mcpTools = mcpClientService.listTools();
    for (McpSchema.Tool mcpTool : mcpTools) {
        ToolDefinition definition = ToolDefinition.builder()
                .name(mcpTool.name())
                .description(mcpTool.description())
                .parameters(objectMapper.valueToTree(mcpTool.inputSchema()))
                .source(ToolDefinition.ToolSource.MCP)  // 标记为 MCP 工具
                .mcpServer("mcp-server")
                .build();

        register(definition);
    }
}

关键点：

  • MCP 工具和本地工具在注册表中是同一层级
  • source 字段决定执行时走哪条路（本地 vs 远程）

6.2 MybatisChatMemoryRepository（MyBatis 实现）

@Slf4j
@Component
@RequiredArgsConstructor
public class MybatisChatMemoryRepository implements ChatMemoryRepository {

    private final ChatMemoryMapper mapper;

    @Override
    public List<Message> findByConversationId(String conversationId) {
        return mapper.findByConversationId(conversationId).stream()
                .map(this::toMessage)  // 数据库行 → Spring AI Message
                .filter(Objects::nonNull)
                .toList();
    }

    @Override
    @Transactional
    public void saveAll(String conversationId, List<Message> messages) {
        mapper.deleteByConversationId(conversationId);  // 先删
        for (int i = 0; i < messages.size(); i++) {
            mapper.insert(toEntry(conversationId, i, messages.get(i)));  // 后插
        }
    }

    // 数据库行 → Spring AI Message
    private Message toMessage(ChatMemoryEntry entry) {
        return switch (entry.getMessageType()) {
            case "USER" -> new UserMessage(entry.getContent());
            case "ASSISTANT" -> new AssistantMessage(entry.getContent());
            case "SYSTEM" -> new SystemMessage(entry.getContent());
            default -> null;
        };
    }

    // Spring AI Message → 数据库行
    private ChatMemoryEntry toEntry(String conversationId, int index, Message message) {
        ChatMemoryEntry entry = new ChatMemoryEntry();
        entry.setConversationId(conversationId);
        entry.setMessageIndex(index);
        entry.setMessageType(message.getMessageType().name());
        entry.setContent(message.getText());
        return entry;
    }
}

关键点：

  • saveAll 是整体替换语义，不是追加！窗口淘汰后旧消息会被删掉
  • @Transactional - 先删后插在同一事务中，保证原子性
  • messageIndex - 消息顺序，不能乱

6.5 conversationId 设计

private String resolveConversationId(ChatRequest request) {
    if (request.getConversationId() != null && !request.getConversationId().isBlank()) {
        return request.getConversationId();
    }
    throw new IllegalArgumentException("conversationId 不能为空");
}

💡 关键洞察

1. 为什么需要 ToolCallbackProvider 这个「桥梁」？

Spring AI 的 Agent Loop 只认 ToolCallback 接口

你的安全机制（白名单、敏感检查、参数校验）在 ToolService 里

ToolCallbackProvider 把两者串起来：Spring AI 调工具时，实际走的是 ToolService 的安全流程

2. 为什么 saveAll 是「整体替换」而不是「追加」？

窗口策略（maxMessages=20）会淘汰旧消息

如果用追加，淘汰的消息永远留在数据库里

整体替换保证数据库和内存中的消息列表一致

3. 为什么 eventName 必须在 while 循环外面声明？

SSE 的 event: 和 data: 可能被拆在两个 TCP 包里

如果在循环里面声明，每次 read() 都会重置，导致事件类型丢失

4. MCP 工具和本地工具为什么在注册表中是同一层级？

对模型来说，它不需要知道工具是本地的还是远程的

统一的工具列表让模型只关心「能调什么」，不关心「在哪执行」

source 字段只在执行时起作用，决定走本地 switch 还是 MCP 协议
