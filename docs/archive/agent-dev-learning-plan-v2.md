# Agent开发学习计划（前端转型 · 19周版 · 旧）

> ⚠️ **已废弃作为进度依据**。请用 `agent-dev-learning-plan-v3.md`（大纲）+ `HANDOFF.md`（现状）。
>
> 背景假设：前端开发者，自学过Java/Spring Boot但无真实后端项目经验，Agent开发零基础。
> 使用方法：每完成一项任务，把标题+问题模板发给大模型深入讲解。遇到卡壳的地方多问"为什么这样设计"而不只是"怎么实现"。

---

## 第一阶段：工程化细节补课（第1周，非从零学CRUD）

> 你已有多个CRUD项目经验，这周不重复造轮子，只针对自学时容易跳过的工程化细节做审查和补强。用你现有项目直接过一遍，视完善程度可能3-5天就够。

- [ ] 1.1 用你现有的一个CRUD项目做分层设计审查（Controller/Service/Repository职责是否清晰）
  - 问大模型：`review这个Spring Boot项目的分层设计，重点看Service层有没有把业务逻辑正确隔离，Controller有没有做参数校验`（附代码）
- [ ] 1.2 补全异常处理机制（全局异常处理器、自定义业务异常）
  - 问大模型：`Spring Boot的@ControllerAdvice全局异常处理最佳实践是什么？帮我review我的实现`
- [ ] 1.3 理解事务边界（@Transactional的坑：自调用失效、传播行为）
  - 问大模型：`@Transactional自调用为什么会失效？给我一个我自己代码里可能踩坑的例子`
- [ ] 1.4 写基本的单元测试和集成测试（不是要求覆盖率，是要有测试意识）
  - 问大模型：`帮我给这个Service方法写JUnit测试，包括正常和异常场景`

**验收标准**：能独立解释你项目里每一层为什么这样分，异常处理和事务边界没有明显漏洞。

---

## 第二阶段：LLM API基础（第2-3周）

- [ ] 2.1 用Java原生HTTP客户端调用Claude/OpenAI兼容API
  - 问大模型：`帮我用OkHttp写一个调用Claude API的最小客户端，不用任何SDK，我要理解底层请求结构`
- [ ] 2.2 实现流式SSE响应解析
  - 问大模型：`Claude API流式响应的event类型有哪些？帮我写Java代码解析并拼接完整文本`
- [ ] 2.3 理解Token计费和上下文窗口限制

**验收标准**：独立写出支持流式输出的LLM调用客户端，能解释SSE和普通HTTP响应的区别。

---

## 第三阶段：Tool Use / Function Calling（第4周）

- [ ] 3.1 理解Tool Schema定义（JSON Schema格式）
  - 问大模型：`给我一个查询天气的工具JSON Schema示例，解释每个字段的作用`
- [ ] 3.2 实现模型触发工具调用到本地执行的完整链路
  - 问大模型：`帮我写Java代码解析tool_use消息，反射调用本地方法，再把结果封装成tool_result发回`
- [ ] 3.3 实现多轮Agent Loop（模型连续调用工具直到给最终答案）

**验收标准**：做出一个支持至少2个工具、多轮循环的最小Agent，能解释循环终止条件怎么判断。

---

## 第四阶段：MCP协议基础（第5-7周）

> MCP是2026年Agent开发的事实标准，被Linux基金会下的Agentic AI Foundation托管，OpenAI、Google、Microsoft都已采用。这是整个计划里投入时间最多的部分。

- [ ] 4.1 理解MCP三大原语（Tools/Resources/Prompts）的设计意图
  - 问大模型：`MCP里Tools和Resources的本质区别是什么？为什么要分开设计，混用会有什么问题`
- [ ] 4.2 用Java MCP SDK搭建最小MCP Server（stdio模式）
  - 问大模型：`帮我用Java MCP SDK写一个最小MCP Server，暴露一个查询DCForge数据的工具`
- [ ] 4.3 用Claude Desktop连接并调试
- [ ] 4.4 理解stdio和Streamable HTTP的区别，把Server改造成Streamable HTTP
  - 问大模型：`为什么生产环境的MCP必须用Streamable HTTP而不是stdio？帮我改造现有代码`
- [ ] 4.5 处理多客户端并发下的session管理

**验收标准**：MCP Server支持Streamable HTTP，能被多个客户端同时连接且session互不干扰。

---

## 第五阶段：Java Agent框架搭建（第8-10周）

> 这是本计划里技术难度最高的阶段，给3周而不是1周，因为涉及框架选型和状态管理这两个你完全陌生的领域。

- [ ] 5.1 对比Semantic Kernel（Java版）和LangGraph4j，选一个深入
  - 问大模型：`Semantic Kernel Java版和LangGraph4j在状态管理成熟度上有什么区别？针对Spring Boot项目推荐哪个，说明理由`
- [ ] 5.2 搭建带对话历史管理的Agent（历史存Redis）
  - 问大模型：`帮我用[选定框架]写一个支持多轮对话历史的Agent，历史用Redis存储，设计一下key的过期策略`
- [ ] 5.3 实现Checkpoint机制（Agent执行中断可恢复）
  - 问大模型：`Checkpoint机制的核心原理是什么？不用Kafka的简化版本，用数据库怎么实现`（先用数据库实现，比直接上Kafka更适合你现在的水平）

**验收标准**：Agent执行到一半重启服务，能从上次状态继续，能解释Checkpoint存的是什么数据。

---

## 第六阶段：前端集成（第11-12周）

> 这是你的强项，节奏可以快，但重点是学会"给Agent设计交互"而不只是渲染数据。

- [ ] 6.1 React端流式渲染Agent输出（打字机效果）
  - 问大模型：`帮我写一个React组件用EventSource处理SSE流并实现打字机渲染`
- [ ] 6.2 可视化Agent执行链路（思考/工具调用/结果）
  - 问大模型：`用Ant Design的Timeline组件设计一个Agent执行过程展示组件`
- [ ] 6.3 敏感操作二次确认交互（复用你已有的AuthButton模式）
  - 问大模型：`参考我这个AuthButton组件的权限判断逻辑，帮我设计Agent执行删除类操作前的二次确认弹窗`（附代码）

**验收标准**：有一个前后端打通的完整Agent demo，敏感操作有确认机制。

---

## 第七阶段：MCP鉴权（第13-14周）

> 挪到这里而不是提前，因为OAuth 2.1流程需要你对MCP的Server/Client架构已经很熟悉才不会混乱。

- [ ] 7.1 理解MCP的OAuth 2.1模型（Server作为resource server）
  - 问大模型：`画一下MCP的OAuth 2.1鉴权时序图，Spring Security怎么配置resource server角色`
- [ ] 7.2 集成Spring Security实现鉴权
- [ ] 7.3 测试未授权/授权请求行为差异

**验收标准**：无token请求被拒绝，有效token请求正常执行。

---

## 第八阶段：可观测性（第15-16周）

- [ ] 8.1 理解OpenTelemetry的span/trace概念
  - 问大模型：`Agent的多步骤工具调用链路，span应该怎么设计层级关系`
- [ ] 8.2 给Agent执行链路埋点并接入日志系统
- [ ] 8.3 验证能在监控平台看到完整调用链

**验收标准**：一次Agent执行的每一步都能在监控系统里串联查看。

---

## 第九阶段：成本控制与多租户（第17-18周）

- [ ] 9.1 设计Redis限流方案（令牌桶算法，按用户维度）
  - 问大模型：`帮我设计基于Redis的令牌桶限流方案，按用户维度限制Agent调用频率`
- [ ] 9.2 实现Token消耗统计与成本归因
- [ ] 9.3 验证多租户数据隔离

**验收标准**：能查询任意用户在任意时间段的调用次数和成本。

---

## 第19周：整合与复盘

- [ ] 10.1 把前面18周的模块整合成一个完整可演示的系统
- [ ] 10.2 写一份技术复盘文档，记录踩过的坑（对你有长期价值）
- [ ] 10.3 评估是否需要学A2A（多智能体协作），默认不需要，除非有明确的多Agent协作场景

---

## 关键节点验收

| 周次 | 验收内容 |
|---|---|
| 第1周末 | 能指出自己现有项目在异常处理/事务边界上的具体漏洞 |
| 第7周末 | MCP Server支持生产级传输（Streamable HTTP） |
| 第12周末 | 前后端打通的完整Agent demo，含权限确认交互 |
| 第18周末 | 具备鉴权、监控、限流、成本统计的基本生产能力 |

## 与原计划的主要差异

- 第一阶段改为审查已有CRUD项目的工程化细节，不重新从零写CRUD（已确认有多个项目经验）
- Checkpoint机制先用数据库实现，Kafka作为进阶内容不列入主线（除非实际业务确实需要消息队列）
- MCP鉴权从原计划的第5周挪到第13周，避免过早接触OAuth 2.1导致的挫败感
- A2A默认不学，除非有明确业务场景
