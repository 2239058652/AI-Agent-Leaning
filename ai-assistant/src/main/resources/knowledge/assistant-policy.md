# AI 助手业务与权限说明

本文是知识库样本文档，不是对话记忆。对话记忆按会话保存用户和模型刚说过的话；本文保存可检索的业务规则，回答时必须能引回本节标题。

## 订单查询范围

普通用户调用 `query_orders` 时，只能看到自己的订单。系统按当前登录用户的 `userId` 过滤，模型不能通过改口令或改会话 id 查到别人的订单。

管理员可以查看所有用户的订单，用于客服排查。管理员查看他人订单仍然是只读查询，不等于获得取消权限的豁免。

## 取消订单

`cancel_order` 是敏感写操作。即使用户有权操作该订单，也必须先弹出确认框，用户确认后才能真正执行。确认不能替代权限校验。

普通用户只能取消自己的订单。若订单属于他人，工具必须直接返回「无权操作」，不得弹出确认框，以免误导用户去确认一次越权操作。

管理员可以取消他人订单，但仍然需要确认。确认记录绑定创建时的用户身份：确认 id 被别人拿到时，既不能执行，也不能把原确认删掉。

## 天气工具

`get_weather` 由独立的 MCP Server 提供，不是本地工具。

请求要进入 `/mcp`，必须携带合法 JWT，并且包含 `SCOPE_mcp.weather`。没有 Token 会被拒绝（401）；有 Token 但没有该 scope 会被拒绝（403）。这一层在工具回调之前。

进入 MCP 之后，`get_weather` 还要求 `ROLE_ADMIN`。普通用户即使有天气 scope，也会收到权限不足的工具错误，不能查天气。管理员可以查指定城市未来几天的天气。

## 会话记忆

聊天接口的 `conversationId` 由前端提供，服务端存储时会加上当前用户前缀，形成 `userId:conversationId`。两个用户使用相同的前端会话 id，也不会读到对方的历史，也不能清空对方的会话。
